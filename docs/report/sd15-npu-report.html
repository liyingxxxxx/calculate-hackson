UNet：从 12.35 秒到 2.67 秒

做法是先求算对，再在真卡上逐个算子计时，每轮只改当时最大的那一项。每一轮都在真卡上对过参照、两遍结果逐字节一致之后才提交。

版本改了什么为什么改它一步段数
第一版生成器从 diffusers 的模块结构自动出全部算子特化和各段程序，按每核代码上限自动切段先求算对12.35 s20
①自写注意力 flash_attn!：一块 key / value 给 64 行 query 共用calBLAS 原版注意力在 64² 一次 625 ms，占了一半时间8.19 s18
②输入超过 1024 通道的卷积改成矩阵乘（3×3 拆成 9 个抽头接着累加）这些卷积只能走慢路，0.1–0.2 TFLOPS，合计约 3.6 s5.16 s10
③自注意力先去掉图的边框像素再算；缩放系数提前乘进 q 的权重带边框时 64² 多算约 34% 的分数，还要掩码4.18 s10
④自注意力一次处理 128 行 query实测时间主要花在每块 key / value 的搬运上3.12 s5
⑤自写矩阵乘 gemm_rows!：一块权重读一次给 4 块数据用，数值与原版逐位相同calBLAS 矩阵乘每 16 行重读一遍权重，1.0–1.5 TFLOPS；新版 2.4–4 TFLOPS2.67 s6

每一版和参照比都在 49.6–50.1 dB 之间，优化没有损失精度。CPU 上的模拟（同一份设备程序在 numpy 里重放）对参照 52.8–53.7 dB。

现在一步 2.67 秒花在哪

解码器

TAESD

整个解码器一个设备程序。整次墙钟中位数 0.113 秒（两次上卡共 15 遍），比同机 CPU 快约 1.6 倍。四组 latent 对 bf16 参照 52.7–65.8 dB。从 GitHub 重新克隆、从零重建后上卡，出图和第一次逐字节相同。

正式 VAE

第一版 6 段程序算对了但要 5.18 秒，比 CPU 慢。按真卡逐算子计时做了三件事：卷积加列块快路、GroupNorm 改成直接在 NHWC 上算（去掉排布转换）、并成 3 段。降到 0.98 秒，比 CPU 快约 1.75 倍，精度不变（58.3 dB）。ComfyUI 节点从 5.89 秒降到 0.99 秒。

摸清的工具链限制

现象（docc / dort 0.4.1）影响怎么处理
每颗核的代码不能超过约 1 MB（RISC-V 跳转范围）大模型一个程序放不下切成多段程序，生成器按实测代码量自动切（UNet 6 段、VAE 3 段）
从「每行一个数」的向量按行切一段再做广播运算：编译通过，真卡上算错注意力第一版输出全错，模拟器查不出用单算子上卡二分定位，改成整块运算；之后新算子都先单独上卡对 numpy
32² × 640 通道的 1×1 卷积，片上缓冲放不下编不出来改走矩阵乘
f32 的向量除法不收；运行时的条件分支里不能有矩阵累加限制算子写法除法放到 bf16 里做；循环保持展开
dort 没有常驻会话，每次调用都重新部署权重UNet 每步多 0.5 秒CFG 两路放在同一次调用里共用一次部署；待组委会确认有没有常驻的办法

工程纪律与可复现

  • 只用赛方公开工具链（rustc 1.98.1-calculet、docc 0.4.1、dort 0.4.1），由环境自检脚本守着；不用机器上另装的老版本，不引用未公开的资料。
  • 每次改动的流程：CPU 模拟对独立参照，然后上真卡（结果须两遍逐字节一致），再跑 14 项自检，最后提交并推送。
  • 真机实测、CPU 实测、模拟、估算分开标注；落回 CPU 的计算会计数并打日志，不静默。
  • 每轮的原始结果（真卡指标、逐算子计时、每段耗时、CPU 对照）都存在仓库 test/results/npu3-20261114/，性能全表在 test/PERF.md，逐项进度在 PROGRESS.md，设计与关键事实在 docs/DESIGN.md，交接文档在 docs/HANDOFF.md。
  • UNet 各轮提交：d45b90e 第一版、9260b1e 注意力、733ce4c 宽通道卷积、6f8517b 稠密 token、c92cfbc 128 行 q、1ca5f4b 矩阵乘。

还没做的

  • UNet 还没接进 ComfyUI 的采样器；工作流里 UNet 仍在 CPU 上。
  • NPU 的 UNet 现在比同机 CPU 慢约 1.9 倍（2.67 秒对 1.41 秒）。
  • CLIP 文本编码还在 CPU 上；去噪循环还没放进设备。
  • 只有 512×512 一个尺寸。
  • UNet 只在一组输入（时间步 500）上对过参照；部分新算子还没有单独的测试项。

下一步（按优先级）

  1. 把 NPU 的 UNet 接进 ComfyUI 的 KSampler，跑通 UNet 和 VAE 都在 NPU 上的完整出图。按现在的速度估算，20 步约 54 秒，CPU 约 49 秒（估算）。
  2. 继续提速，目标每步低于 CPU 的 1.41 秒：64² 自注意力（0.84 秒，0.41 TFLOPS）和 64² / 32² 的卷积（0.50 秒）。
  3. 向组委会确认 dort 有没有常驻会话或跳过部署的办法；有的话每步能省 0.5 秒。
  4. CLIP 上 NPU；加更多分辨率档位。
