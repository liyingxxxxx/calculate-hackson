## 一、原粒半导体赛道说明（五道题）

原粒半导体自研的端侧 AI 芯片（NPU）上做开发，让模型跑得更快、更省电。

背景

现在很多 AI 应用依赖云端，延迟高，隐私风险也大。原粒半导体做端侧 AI 推理芯片和配套软件栈，自研的 NPU 能让 AI 在本地运行。原粒半导体邀请你在它的 NPU 平台上做算子开发与性能优化、模型特性适配或应用创新。作品要做成能运行、能验证、能复用的工程成果，并用测试说明功能、性能，以及 NPU 实际贡献了多少。

五道题，选一道

标准题一到四有能运行的基线、接口规格和测试要求。也可以做开放题五，围绕 NPU 自己提应用、工具或计算任务，自己定目标和验收方法。

| 题 | 做什么 | 交什么、怎么验 |
| --- | --- | --- |
| 一、NPU 融合算子开发与性能优化 | 按提供的接口，把指定的几个连续计算步骤合成一个算子执行，比如把残差加法和归一化合成一个，减少中间数据的读写和搬运 | 交代码、正确性和边界测试、调用样例、性能报告。先跟独立参考结果对比确认正确，再看执行速度、内存占用和数据搬运量的变化 |
| 二、NPU 选择与采样算子开发 | 模型生成内容时，要从多个候选里选下一步输出。在 Top-K、Top-P 或相关操作里选一项，在 NPU 上实现，接入给定样例 | 测选择结果和边界输入；涉及随机采样的，检验输出分布；再比执行速度。不能降低精度要求或缩减功能 |
| 三、模型关键特性的 NPU 适配 | 选定并固定一个上游版本和一个小模型，针对位置编码、注意力掩码或归一化等一项具体功能，完成在 NPU 上运行所需的适配 | 交代码、测试和运行样例；模型能正常加载和推理，输出跟参考结果一致；说明支持范围和已知限制 |
| 四、基于 NPU 的本地检索与重排应用 | 用指定的公开或合成资料，做本地检索或重排，比如根据问题找出相关段落，或者把搜索结果按相关程度排序。至少一个约定的核心计算环节要在 NPU 上执行 | 测检索或排序效果和整个流程的耗时；说明 CPU 和 NPU 各负责哪些任务 |
| 五（开放题）、基于 NPU 的创新应用与技术探索 | 不限于前四题，可以围绕视觉、语音、数据处理或别的场景，自己设计用 NPU 的应用、开发工具或计算任务 | 说明要解决什么问题、用什么方案、哪些核心计算由 NPU 完成、怎么测效果；交能运行的作品和测试结果 |

能用什么

现场有 5 台原粒 NPU 真机，选原粒半导体赛道的队共用。怎么排队用，开赛后通知。
SDK、文档和基线怎么拿，开赛后通知。SDK、设备和允许修改的范围，以原粒半导体的说明为准，包括 SDK 能不能放进公开仓库；开放题需要的接口和资源，以比赛提供的为准。

规则提示

代码、测试、运行说明、评测结果和已知限制，放进代码仓库和项目说明；写清哪些计算在 NPU 上执行、哪些回退到 CPU。
不能用远程服务调用代替本地实现。
统一设备、版本和输入；编译、加载、预热和推理时间分开记。真机实测、仿真和估算要分清楚，性能成绩以统一复测为准。
只用获准的设备和资料，不碰别人的数据。真机测试按现场的安排来，不自己刷写或复位共享设备。
没公开的资料不能上传到外部 AI 工具；路演和展示里要放原粒半导体的资料，先给他们的工程师看一眼。发现疑似安全漏洞，先停下，私下告诉他们的工程师。

原粒半导体评委看重什么

先看授权合规和基础正确性：数值题跟独立参考对比，在约定容差内；要求逐位一致的，逐字节验收；开放题按你们讲清的目标和验收方法验证，核心计算必须真的用到 NPU。
再看功能是否正确、性能或应用价值、能否复现，以及 NPU 实际贡献了多少。工程上看能不能按说明独立复现、文档清不清楚、交的材料齐不齐、跟演示对不对得上；已有成果、CPU 承担的计算和测试范围，要如实说明。

## 二、选手快速开始（配置文档）

# Calculet NPU 黑客松 · 选手快速开始

赛题文档：http://115.159.82.89/

## 1. 环境

- Linux x86_64
- 已安装 rustup（https://rustup.rs ，国内可用 https://rsproxy.cn ）
- git

## 2. 安装工具链

```bash
curl -sSf http://115.159.82.89/install.sh | sh
```

装好后有一个名为 `calculet` 的工具链（rustc 1.98.1 + NPU 设备 target），以及 `docc`、`dort` 两个命令。

## 3. 获取代码

三个仓库放在同一目录下：

```bash
for r in calBLAS calDNN npu; do git clone http://115.159.82.89/git/calculet/$r.git; done
```

| 仓库 | 内容 |
| --- | --- |
| npu | 写 kernel 的基础库：存储空间、tile、原语、`#[npu::kernel]`（语法见 SYNTAX.md） |
| calDNN | 算子接口与图 API |
| calBLAS | 算子库与模型例子（`examples/`），已有算子见 README |

## 4. 编译第一个例子

```bash
cd calBLAS
cargo build -p tiny --lib --target dopamine-unknown-none-elf
ls target/dopamine-unknown-none-elf/npu/    # tiny.cvxo（CalVX 目标文件）、tiny.cvx（可读汇编）
```

仓库里已配置好工具链，进入目录后 cargo 会自动使用 `calculet`。

## 5. 在自己的工程里引用

```toml
# .cargo/config.toml
[registries.calculet]
index = "sparse+http://115.159.82.89/git/api/packages/calculet/cargo/"

# rust-toolchain.toml
[toolchain]
channel = "calculet"

# Cargo.toml
[dependencies]
npu = { version = "0.1.0", registry = "calculet" }
caldnn = { version = "0.1.0", registry = "calculet" }
calblas = { version = "0.1.0", registry = "calculet" }
```

## 6. 说明

- 代码仓库和包源都可以匿名访问，不需要账号。
- 只需要写 Rust；`.cvx` 只用来调试。
- 真机资源有限，请先在本地把设备遍编通。
- 提交方式与 FAQ 另行发布。

## 三、赛题要求（Calculet NPU CalVX 算子与端到端模型移植黑客松 · 选手赛题文档）

快速开始工具链仓库与 cargo 源参赛路线提交与 FAQ代码仓库快速开始（Markdown）

Calculet NPU CalVX 算子与端到端模型移植黑客松
选手赛题文档

1. 简介

在 Calculet NPU 上，算子用 Rust 编写：npu 库提供显式存储空间、tile、原语和 #[npu::kernel]，calculet 工具链把 kernel 编译成 CalVX。CalVX 是跨代的虚拟指令集，定位类似 CUDA 的 PTX；CalVX 再由 docc 生成 NPU 原生指令，在真机上运行。

当前 Calculet 的算子库（calBLAS）主要覆盖大语言模型，Stable Diffusion、SAM 图像分割、视频生成等 CV / 多模态模型需要的大量算子还没有实现。本次黑客松邀请开发者补齐算子生态：可以实现独立算子，也可以补齐整套依赖算子、打通开源推理前端，完成端到端模型的 NPU 推理。端到端打通、对接 ComfyUI 等生态的成果评价权重更高。

技术链路

- 用 Rust 写 kernel（#[npu::kernel]），可以直接复用 calBLAS 的 kernel 模板与片段
- cargo build --target dopamine-unknown-none-elf：设备遍，产出 CalVX 目标文件 .cvxo 和可读汇编 .cvx
- 主机遍（cargo run）：按 calDNN 的图 API 编排整模型的计划
- 平台侧：docc 把 CalVX 生成 NPU 原生指令并打包成 calbin，dort 在真机上运行

只写 Rust，不需要手写 CalVX；.cvx 只用来调试、排查问题。真机资源有限，存在排队延迟，请先在本地把设备遍编通。

2. 快速开始

需要 Linux x86_64 和 rustup（国内可用 rsproxy.cn 安装）。

```bash
# 1. 安装 calculet 工具链（rustc 1.98.1 + 设备 target + docc + dort）
curl -sSf http://115.159.82.89/install.sh | sh

# 2. 取代码：三个仓库并排放在同一目录
for r in calBLAS calDNN npu; do git clone http://115.159.82.89/git/calculet/$r.git; done

# 3. 设备遍：编一个最小例子
cd calBLAS
cargo build -p tiny --lib --target dopamine-unknown-none-elf
ls target/dopamine-unknown-none-elf/npu/      # tiny.cvxo  tiny.cvx

# 全部例子
cargo build --workspace --lib --target dopamine-unknown-none-elf
```

各仓库的 rust-toolchain.toml 已经写好 channel = "calculet"，进入目录后 cargo 会自动使用 calculet 工具链。

3. 工具链

| 组件 | 说明 |
| --- | --- |
| rustc / cargo | rustc 1.98.1 加 CalVX 代码生成后端；cargo、rustfmt、clippy 与官方 1.98.1 相同 |
| dopamine-unknown-none-elf | 设备 target：kernel ⇒ CalVX（.cvxo / .cvx） |
| dopamine-unknown-none-cvx | 设备 target：只出 .cvxo |
| docc | calbin 打包、检查、比对（docc calbin from-calvx / doctor / diff）与 ELF 反汇编；只提供二进制 |
| dort | Calculet 加速卡的设备管理与运行（需要真机）；只提供二进制 |

安装脚本做的事情（也可以手动执行）：

```bash
RUSTUP_DIST_SERVER=http://115.159.82.89 rustup toolchain install nightly-2026-11-13 --profile minimal
rustup toolchain link calculet "$(rustup run nightly-2026-11-13 rustc --print sysroot)"
# docc / dort 在工具链的 bin/ 里，脚本会链到 ~/.cargo/bin
```

可选组件：RUSTUP_DIST_SERVER=http://115.159.82.89 rustup component add --toolchain nightly-2026-11-13 rustfmt clippy rust-src。

4. 仓库与 cargo 源

| 仓库 | crate | 内容 |
| --- | --- | --- |
| npu | npu、npu-macros | 写 kernel 的基础库：显式空间、tile、原语、#[npu::kernel]（语法见 SYNTAX.md） |

已有算子请先查 calBLAS 的 README（覆盖表），避免重复实现。

5. 参赛路线（自由选择，可迭代升级）

路线 A：算子开发

实现 calBLAS 中不存在的算子，支持单算子或融合算子：Diffusion、SAM、视频模型依赖的基础运算、归一化、采样、卷积变种、多维张量运算等。

要求：设备遍编译通过，真机输出与 CPU 参考满足精度要求，算子能通过 calDNN 的引擎表注册、被图调用。

路线 B：端到端模型移植（高价值方向）

补齐目标模型缺失的全部算子并完成推理前端的桥接适配，在 Calculet NPU 上跑通完整模型推理。推荐目标：

- Stable Diffusion 系列：对接 ComfyUI 原生工作流，由 ComfyUI 发起推理请求，计算全部在 NPU 上完成，产出图像
- SAM 图像分割：产出分割掩码
- 视频生成模型

判定重点不是零散的算子集合，而是由原生前端下发任务、计算全部在 NPU 上完成、不依赖 CPU 兜底大量算子。能一键拉起 ComfyUI 工作流、稳定出图、支持多尺寸输入的方案是本次赛事的标杆成果。

可以从路线 A 起步，截止前升级到路线 B；评审以最终提交的最高阶成果判定路线，报名时不锁定赛道。
